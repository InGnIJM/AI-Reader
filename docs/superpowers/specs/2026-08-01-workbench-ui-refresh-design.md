# 工作台 UI 焕新设计规格

> 日期：2026-08-01  
> 状态：设计已确认，待规格审阅  
> 范围：桌面端代码分析工作台的窗口标题栏、上下文导航、操作组件与亮暗主题视觉系统

## 1. 目标

将当前工作台从“功能可用的三栏布局”升级为更具产品辨识度、适合长时间阅读与分析的桌面学习工具界面，同时不改变项目、会话、分支、分析、批注及 IPC 的业务行为。

本次改造的体验目标如下：

- 程序标题不再只是系统栏中的灰色文字，而成为清晰、稳定的品牌入口。
- 用户始终能通过页首路径理解自己所在的学习空间、项目、会话和分支上下文。
- 主、次、图标、文字和输入操作具有一致的视觉层级与状态反馈。
- 暗色主题更纯粹、更有沉浸感；亮色主题避免纯白，以暖灰与矿物蓝建立专业但不冰冷的阅读环境。
- 既有键盘可访问性、图标标签、窗口控制与窄窗口布局不回退。

## 2. 已确认的设计决策

| 设计域 | 已确认方案 | 结论 |
| --- | --- | --- |
| 页首导航 | C：上下文导航 | 使用层级路径表达当前位置，不新增顶级路由菜单。 |
| 程序标题 | T2：一体化标题栏 | 左侧品牌区与 Windows 原生窗口控制处于同一视觉栏；面包屑单独位于第二行。 |
| 暗色主题 | 纯黑金 | 使用接近纯黑的背景、深灰表面、克制金色强调。 |
| 亮色主题 | 暖灰 + 矿物蓝 | 不使用纯白背景；主操作采用深矿物蓝。 |
| 操作组件 | A：软胶囊 | 按钮、图标按钮、输入发送控件采用胶囊形；卡片和容器保留较小圆角。 |

## 3. 信息架构与布局

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ [品牌图标] AI 学习助手 · 深度学习空间                       —  □  ×      │
├──────────────────────────────────────────────────────────────────────────┤
│ 学习空间  ›  项目：{project}  ›  会话：{session}  ›  分支：{branch}       │
├──────────────────┬─────────────────────────────────┬─────────────────────┤
│ 项目、文档与会话 │ 分析对话、内容和阅读区域         │ 工具轨迹与批注      │
│ 侧栏             │                                 │ 侧栏                │
├──────────────────┴─────────────────────────────────┴─────────────────────┤
│                            AI 提示输入区                             │
└──────────────────────────────────────────────────────────────────────────┘
```

### 3.1 标题栏

- 标题栏高度为 48px，左侧显示现有应用图标、`AI 学习助手` 和定位语 `深度学习空间`。
- Windows 右上角继续使用 Electron/Windows 提供的最小化、最大化和关闭控件；本次不在渲染进程中实现替代控件。
- 标题栏的空白部分可拖拽窗口；品牌、主题切换、面包屑和其他按钮必须显式退出拖拽区域，保证点击可靠。
- Windows 启用标题栏覆盖层，以便产品标题、窗口控制和背景色形成一个整体。非 Windows 平台保留其原生标题栏行为，不引入平台不一致的自绘控制。
- 不新增新的品牌图片资产；品牌图标继续复用现有应用图标，以避免未经确认的 Logo 变更。

### 3.2 上下文导航

- 第二行高度为 40px，显示可用的上下文段：`学习空间 › 项目 › 会话 › 分支`。
- 当前段使用主题主色和更高字重，其余段使用次级文字色；分隔符保持低对比度。
- 未选择项目、会话或分支时省略对应段，不显示占位文本、空分隔符或错误路径。
- 已有选择处理器的上级段可以点击返回对应上下文；当前段仅作为状态文本，避免制造无效动作。
- 当窗口不足以显示完整路径时，保留当前段和最左侧应用语义，中间段按优先级截断，并通过原生 `title` 提供完整内容。
- 现有工作台顶部的分支选择器保留其切换功能，但在视觉上与新的上下文行对齐，不重复表达同一层级。

## 4. 操作组件规范

### 4.1 形状与尺寸

| 组件 | 基础尺寸 | 形状 | 用途 |
| --- | --- | --- | --- |
| 主按钮 | 最小高度 36px | 胶囊 | 一屏唯一的主要提交/执行动作，如“开始分析”。 |
| 次按钮 | 最小高度 36px | 胶囊 | 保存、创建分支等重要但次级动作。 |
| 文字按钮 | 最小高度 32px | 无填充胶囊命中区 | 取消、恢复、辅助动作。 |
| 图标按钮 | 36×36px 命中区 | 圆形 | 主题、搜索、更多、导出等有 `aria-label` 的图标操作。 |
| 输入框 | 最小高度 40px | 胶囊容器 | AI 提示、批注问题和可输入文本。 |
| 发送按钮 | 28×28px | 圆形 | 位于输入框内，始终保有文字或无障碍标签。 |
| 卡片/面板 | 无固定高度 | 10–12px 圆角 | 用于内容分组，避免与胶囊操作控件混淆。 |

### 4.2 状态

- `hover`：仅调整背景色、边框色和低级阴影，持续 150–200ms。
- `pressed`：使用更深/更浅的主题色阶，不使用会造成布局跳动的位移或缩放。
- `focus-visible`：2px 主题色焦点环并保留适当偏移，不能被表面或阴影吞没。
- `disabled`：保留原有语义禁用属性，使用低强调度与 `not-allowed` 光标，不允许点击。
- `loading`：异步主操作禁用重复提交，并在原有标签附近显示紧凑进度反馈，按钮宽度不变化。

### 4.3 视觉层级

- 每个操作区域只有一个主按钮。
- 主按钮为实底主题色；次按钮为透明/浅表面加边框；文字按钮无填充；图标按钮使用低强调状态层。
- 结构图标继续使用 Material Symbols Rounded，不使用 emoji 或混合图标体系。

## 5. 主题 token 映射

所有组件继续引用语义 token，禁止在组件模块 CSS 中新增未经抽象的主题色值。

### 5.1 亮色：暖灰 + 矿物蓝

| 语义角色 | 值 | 用途 |
| --- | --- | --- |
| 应用背景 | `#F2F1ED` | 主阅读环境，避免纯白刺眼。 |
| 最低表面 | `#FBFAF7` | 内容画布、输入与标题栏表面。 |
| 容器表面 | `#E9E9E4` | 侧栏、选中层与次级容器。 |
| 主文本 | `#202523` | 标题、正文与主要图标。 |
| 次级文本 | `#68716F` | 辅助标签、未选路径与提示。 |
| 主色 | `#285F8F` | 主操作、当前面包屑、焦点环。 |
| 主色容器 | `#DCE9F2` | 选中背景、轻量强调。 |
| 边框 | `#DEDED7` | 面板、分隔线与表面层级。 |

### 5.2 暗色：纯黑金

| 语义角色 | 值 | 用途 |
| --- | --- | --- |
| 应用背景 | `#080808` | 纯黑基底。 |
| 最低表面 | `#10100F` | 主内容画布与标题栏。 |
| 容器表面 | `#171510` | 侧栏和次级容器。 |
| 高层容器 | `#211E17` | 菜单、强调卡片和悬浮表面。 |
| 主文本 | `#F2EAD8` | 标题、正文和主要图标。 |
| 次级文本 | `#A69B89` | 次要信息和未选路径。 |
| 主色 | `#D4AF4F` | 品牌、当前路径、主操作与焦点。 |
| 主色容器 | `#3B3018` | 选中背景和低强调状态层。 |
| 边框 | `#332B1C` | 表面分隔和低对比轮廓。 |

### 5.3 可访问性约束

- 普通正文和控件文字在各自背景上的对比度不低于 4.5:1。
- 大号文本、图标和非文字边界至少满足 3:1；关键焦点环优先达到 4.5:1。
- 颜色不能作为当前路径、运行中、失败或禁用状态的唯一信息来源；状态文本、图标或可读标签继续存在。
- 两种主题的边框、选择态、禁用态和焦点态独立验证，不能由另一主题推断。

## 6. 实现边界

### 包含

- `BrowserWindow` 的 Windows 标题栏覆盖层配置。
- 工作台页首的品牌栏与上下文导航。
- 与标题栏、工作台、侧栏、输入区和批注区相关的布局调整。
- 通用与既有按钮、图标按钮、输入控件的形状、状态和主题 token 迁移。
- 亮色和暗色主题 token 更新，以及主题切换后的视觉验证。
- 对新增组件、路径降级、主题行为与窗口配置的单元测试。

### 不包含

- 新增顶级页面、路由、资料库或学习记录功能。
- 修改项目、会话、分支、批注、导出或分析服务的数据结构与 IPC 契约。
- 更换应用图标、引入外部设计资产或重做 Material Symbols 图标体系。
- 更改 macOS/Linux 的系统窗口控制模型。

## 7. 实施顺序

按已确认的业务优先级实施，而不是一次性替换全局样式：

1. **页首导航与标题栏**：先建立 Windows 标题栏覆盖层、品牌栏、拖拽区域和上下文导航；确认它不破坏窗口控制、分支切换和窄窗口布局。
2. **按钮与操作控件**：将主、次、文字、图标按钮及输入发送区迁移到软胶囊规范，补齐状态反馈和无障碍语义。
3. **双主题 token**：在既有 token 架构内替换亮色和暗色映射，并移除涉及区域中遗留的硬编码主题色。
4. **全局联调**：复核工作台三栏、阅读器、批注、导出、分支和主题切换的视觉一致性。

## 8. 测试与验收

### 8.1 TDD 范围

- 先为标题栏、上下文段过滤、当前段高亮和窄宽度文本策略编写失败的渲染测试。
- 先为交互子元素退出拖拽区域、图标按钮标签和主题切换结果编写失败测试。
- 先为按钮的禁用、加载、焦点可见性相关的 DOM 语义编写失败测试。
- 每个新增或修改的 TypeScript 模块在相邻 `test/` 目录中持久化 Vitest 测试，并覆盖正常、边界和异常/降级分支。

### 8.2 验收标准

- Windows 标题栏显示品牌区，且最小化、最大化、关闭始终保持可用。
- 页首能正确显示当前可用的学习空间、项目、会话和分支路径；不存在空段或重复路径。
- 亮色模式不出现大面积纯白，矿物蓝的主操作清晰可辨；暗色模式的基础背景为纯黑。
- 主、次、文字、图标、输入和发送操作遵循软胶囊尺寸与状态规范。
- 两个主题中的键盘焦点均可见，图标按钮保留可读标签，禁用控件不可触发动作。
- 相关桌面端 Vitest 测试及全量 `pnpm test` 通过；核心新增模块覆盖率达到项目要求。

## 9. 规格自检

- 不存在未确定的设计选项、占位符或待定色彩值。
- 标题栏、上下文导航、主题 token、操作组件和测试目标彼此一致。
- 范围限制明确：本次只做 UI 表达与窗口框架，不改变业务模型或新增产品功能。
- 实施顺序与用户确认的优先级一致：页首导航与标题栏、按钮、配色、全局联调。
