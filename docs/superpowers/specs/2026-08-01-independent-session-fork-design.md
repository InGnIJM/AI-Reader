# 独立会话分叉设计

## 目标

修复含分叉会话无法删除的问题，并将“分支”定义为独立的会话快照：从某一轮对话创建分支时，生成一份可独立删除、继续和导出的新会话。

## 用户行为

- 会话入口提供“创建分支”操作，以当前活跃轮次为分叉点。
- 每轮对话提供“从此处创建分支”操作，以该轮为分叉点。
- 创建后自动切换到新会话；新会话与原会话在侧栏中同级展示。
- 新会话标题默认为“原会话标题 · 分支”。
- 新会话包含从首轮到分叉点的所有对话轮次，以及其批注和讨论记录。
- 原会话与新会话此后互不依赖：任一会话可单独删除，不影响另一会话。

## 数据模型与兼容性

不再用 `analysis_branches` 表表达用户可见的分支。创建分支会建立新的 `analysis_sessions` 记录，并复制被选路径上的：

1. `analysis_documents`，保留顺序并重写 `session_id`、`branch_id` 和路径内的 `parent_document_id`。
2. `analysis_tool_traces`，把 `analysis_document_id` 映射到复制后的轮次。
3. `analysis_annotations`，把 `analysis_document_id` 映射到复制后的轮次。
4. `analysis_discussion_messages`，把 `annotation_id` 映射到复制后的批注。

每个新会话保留一个主分支，仅用于满足现有轮次表的结构约束；该分支不与源会话、源分支或源文档保留引用关系。该方案不需要重建现有表：旧的同会话分叉数据继续可读，删除时由触发器修复保证安全；所有新建分叉均采用独立会话副本。

## 删除修复

删除会话时，SQLite 外键级联会对 `analysis_branches` 产生多个中间更新。现有通用 `BEFORE UPDATE` 校验在 `head_document_id` 被清空、而 `forked_from_document_id` 尚未被清空的短暂状态中错误中止删除。

触发器校验将限定在其对应的外键字段或 `session_id` 实际改变时执行。这样仍阻止跨会话写入，却不会把合法级联删除的中间状态当作数据损坏。

## UI

- 在会话页头或现有会话操作区域增加创建分支按钮，禁用状态与运行中的会话操作一致。
- 在对话时间线每一轮增加从此处创建分支按钮。
- 两个入口复用同一个创建独立会话的动作；仅分叉点不同。
- 创建成功后刷新会话集合、选中新会话并加载其复制后的最后一轮。
- UI 继续使用 Material Symbols，提供中英文可访问标签与提示文本。

## 错误处理

- 没有可分叉的活跃轮次时，会话入口禁用。
- 分叉点不属于当前会话时，主进程拒绝请求，不写入任何记录。
- 复制过程包裹在单个 SQLite 事务中；任一步失败均回滚。
- 会话删除与分叉复制分别具备回归测试，确保删除源会话不会影响复制出的会话。

## 测试

- 数据库触发器：删除含 fork 关系的旧会话成功，跨会话引用仍被拒绝。
- 会话服务：从指定轮次复制会话、轮次链、批注和讨论；源与副本可分别删除。
- IPC：创建独立会话分叉的参数和错误路径。
- 渲染器：会话入口和每轮入口都发送正确的分叉点，并在成功后切换到新会话。
