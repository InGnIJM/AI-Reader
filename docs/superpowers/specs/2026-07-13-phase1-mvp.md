# AI Learning Agent - Phase 1 MVP 设计规范

> 版本：v2.0 | 日期：2026-07-13 | 状态：待审查
>
> v2.0 更新：收缩 MVP 范围，移除 RAG/向量检索/长期记忆/复杂 Agent 编排，聚焦最小闭环验证

---

## 一、目标

### 核心验证命题

先把「文档变成可阅读的 AI 学习材料，并能围绕内容进行批注讨论」做好。

### 最小闭环

```
导入文档
   ↓
解析文档结构
   ↓
AI 根据原文生成导读文档
   ↓
用户阅读 AI 文档
   ↓
选中文字创建批注或提出问题
   ↓
AI 结合选中文字和章节上下文回答
   ↓
保存批注与对话
```

### MVP 验收标准

#### 文档导入
- [ ] Markdown、TXT、文本 PDF 可以正常导入
- [ ] 导入后可以看到章节目录
- [ ] 失败时有明确错误信息
- [ ] 应用重启后文档仍然存在

#### AI 生成文档
- [ ] 能根据导入内容生成学习大纲
- [ ] 能按照大纲逐节生成 Markdown
- [ ] UI 能显示生成进度
- [ ] 某一节失败后可以重试
- [ ] 已完成章节不会因单节失败而丢失

#### AI 批注
- [ ] 用户可以选中 AI 文档中的文字
- [ ] 可以输入问题或创建普通批注
- [ ] AI 回答包含选中内容和当前章节上下文
- [ ] 支持流式显示、停止、重试和追问
- [ ] 重启应用后批注和对话仍然存在
- [ ] 点击批注能够重新定位到对应文字

## 三、核心能力设计

### 3.1 文档导入

**支持格式**：Markdown、TXT、文本型 PDF（暂不处理扫描件、复杂公式、双栏论文）

**导入流程**：

```
用户选择文件
→ 计算文件 Hash（SHA256）
→ 复制到工作区目录
→ 提取文本
→ 按章节/段落切分
→ 保存 documents 和 chapters
→ 进入文档生成页面
```

**数据模型**：

```typescript
interface Document {
  id: string;
  workspaceId: string;
  fileName: string;
  fileType: 'pdf' | 'markdown' | 'txt';
  fileHash: string;
  title: string;
  rawText: string;
  status: 'importing' | 'ready' | 'failed';
  createdAt: string;
}

interface Chapter {
  id: string;
  documentId: string;
  index: number;
  title: string;
  level: number;
  content: string;
}
```

### 3.2 AI 生成学习文档

**简化版两阶段生成**（不必完整实现 STORM）：

**阶段一：生成大纲**

将原始文档的标题、目录、章节摘要、截断后的关键内容发送给 LLM，生成学习导读大纲。

```json
{
  "title": "编译原理学习导读",
  "sections": [
    {
      "title": "编译器整体结构",
      "sourceChapterIds": ["chapter-1"]
    },
    {
      "title": "词法分析",
      "sourceChapterIds": ["chapter-2"]
    }
  ]
}
```

**阶段二：分节生成正文**

按照大纲逐节调用 LLM：

```
原始章节内容
+ 当前导读章节标题
+ 写作要求
→ 生成对应学习文档内容
```

**建议生成内容包含**：
- 章节目标
- 核心概念
- 原理讲解
- 示例
- 容易混淆的内容
- 本章小结
- 思考题

**中间状态持久化**（必须）：

```typescript
interface GenerationJob {
  id: string;
  documentId: string;
  status: 'pending' | 'generating_outline' | 'generating_sections'
    | 'completed' | 'failed' | 'cancelled';
  totalSections: number;
  completedSections: number;
  errorMessage?: string;
}

interface GeneratedArticle {
  id: string;
  sourceDocumentId: string;
  title: string;
  outlineJson: string;
  content: string;
  status: 'generating' | 'completed' | 'failed';
  createdAt: string;
  updatedAt: string;
}

interface GeneratedSection {
  id: string;
  articleId: string;
  index: number;
  title: string;
  sourceChapterIds: string;  // JSON array
  content: string;
  status: 'pending' | 'generating' | 'completed' | 'failed';
  retryCount: number;
  errorMessage?: string;
}
```

**优势**：
- 某一节生成失败时，只重试当前章节
- 已完成章节不会丢失
- 支持进度展示
- 后续可局部重生成

### 3.3 AI 批注

**上下文构建**（无需向量检索）：

```typescript
interface AnnotationContext {
  selectedText: string;
  paragraphText: string;
  previousParagraph?: string;
  nextParagraph?: string;
  currentSection: string;      // 当前 AI 文档章节全文
  question: string;
  discussionHistory: ChatMessage[];
}
```

**支持的能力**：
- 概念解释
- 举例说明
- 翻译
- 内容总结
- 为什么这样做
- 进一步推导
- 针对当前章节追问

**暂不支持**：
- 跨章节语义检索
- 全书相关内容自动召回
- 跨文档知识关联
- 长期阅读记忆

**UI 提示**：「当前 AI 回答基于选中内容和当前章节」

### 3.4 文本锚点

虽然向量索引可以延期，但文本锚点必须实现正确，否则重新打开文档后批注位置会丢失。

**简化锚点**：

```typescript
interface TextAnchor {
  sectionId: string;
  startOffset: number;
  endOffset: number;
  exactText: string;
  prefix: string;   // 前 50 字符
  suffix: string;   // 后 50 字符
}
```

**创建批注时**：必须基于 AI 文档章节的真实内容生成，不能使用占位上下文。

**定位顺序**：

```
offset 校验
→ exactText 匹配
→ prefix + exactText + suffix 匹配
→ 标记为"需要重新定位"
```

不必第一版就做复杂的模糊匹配。

## 四、LLM 接口设计

### 最小接口

```typescript
interface ILLMProvider {
  chat(request: ChatRequest): Promise<ChatResponse>;

  stream(
    request: ChatRequest,
    options?: {
      signal?: AbortSignal;
    }
  ): AsyncIterable<LLMStreamEvent>;

  healthCheck(): Promise<HealthStatus>;
}
```

### 当前只实现 OpenAICompatibleLLMProvider

可兼容：
- OpenAI
- DeepSeek
- 硅基流动
- 本地 Ollama OpenAI-compatible API
- 其他兼容 `/v1/chat/completions` 的平台

暂不需要为 Claude、Gemini 等单独开发 Provider。

## 五、数据库表设计

### 核心表

```sql
-- 工作区
CREATE TABLE workspaces (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- 文档
CREATE TABLE documents (
  id TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  file_name TEXT NOT NULL,
  file_type TEXT NOT NULL,
  file_hash TEXT NOT NULL,
  title TEXT,
  raw_text TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'importing',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- 章节
CREATE TABLE chapters (
  id TEXT PRIMARY KEY,
  document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  index INTEGER NOT NULL,
  title TEXT NOT NULL,
  level INTEGER NOT NULL DEFAULT 1,
  content TEXT NOT NULL
);

-- AI 生成的文章
CREATE TABLE generated_articles (
  id TEXT PRIMARY KEY,
  source_document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  outline_json TEXT,
  status TEXT NOT NULL DEFAULT 'generating',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- AI 生成的章节
CREATE TABLE generated_sections (
  id TEXT PRIMARY KEY,
  article_id TEXT NOT NULL REFERENCES generated_articles(id) ON DELETE CASCADE,
  index INTEGER NOT NULL,
  title TEXT NOT NULL,
  source_chapter_ids TEXT NOT NULL,  -- JSON array
  content TEXT,
  status TEXT NOT NULL DEFAULT 'pending',
  retry_count INTEGER NOT NULL DEFAULT 0,
  error_message TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- 生成任务
CREATE TABLE generation_jobs (
  id TEXT PRIMARY KEY,
  document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  status TEXT NOT NULL DEFAULT 'pending',
  total_sections INTEGER NOT NULL DEFAULT 0,
  completed_sections INTEGER NOT NULL DEFAULT 0,
  error_message TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- 批注
CREATE TABLE annotations (
  id TEXT PRIMARY KEY,
  article_id TEXT NOT NULL REFERENCES generated_articles(id) ON DELETE CASCADE,
  section_id TEXT NOT NULL REFERENCES generated_sections(id) ON DELETE CASCADE,
  -- 锚点信息
  anchor_start_offset INTEGER NOT NULL,
  anchor_end_offset INTEGER NOT NULL,
  anchor_exact_text TEXT NOT NULL,
  anchor_prefix TEXT NOT NULL,
  anchor_suffix TEXT NOT NULL,
  -- 批注内容
  type TEXT NOT NULL DEFAULT 'note',
  content TEXT,
  -- 元数据
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

-- 讨论消息
CREATE TABLE discussion_messages (
  id TEXT PRIMARY KEY,
  annotation_id TEXT NOT NULL REFERENCES annotations(id) ON DELETE CASCADE,
  role TEXT NOT NULL,  -- 'user' | 'assistant'
  content TEXT NOT NULL,
  model_id TEXT,
  token_usage TEXT,  -- JSON
  created_at TEXT NOT NULL
);

-- LLM 使用记录
CREATE TABLE llm_usage_records (
  id TEXT PRIMARY KEY,
  request_type TEXT NOT NULL,  -- 'outline' | 'section' | 'annotation'
  model_id TEXT NOT NULL,
  input_tokens INTEGER NOT NULL,
  output_tokens INTEGER NOT NULL,
  cost REAL,
  created_at TEXT NOT NULL
);

-- 应用设置
CREATE TABLE app_settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

## 七、Phase 2 延期功能

以下功能已从 Phase 1 移除，待核心闭环稳定后在 Phase 2 实现：

| 功能 | 延期原因 |
|------|---------|
| LanceDB 向量存储 | 当前批注只使用当前章节上下文 |
| @xenova/transformers Embedding | 无向量检索需求 |
| Vector Indexer | 暂不需要 |
| Reading Memory | 增加数据模型和上下文复杂度 |
| IMemoryManager 接口 | 当前只需按批注查询历史消息 |
| 两档模型路由 | 第一版一个模型即可 |
| 自动降级机制 | 后续多模型时再实现 |
| 多厂商 LLM 适配 | 先实现 OpenAI-compatible |
| LangGraph 复杂 Agent | 普通状态机已足够 |
| Tool Calling | 当前 AI 不需要调用外部工具 |
| Companion Compiler 完整索引 | 先只生成章节列表和摘要 |
| 蒸馏系统 | 不属于当前三个核心能力 |
| 团队工作区 | 单机单用户优先 |
| 定时任务 | 当前没有实际使用场景 |
| EPUB 支持 | 先支持 MD/TXT/PDF |
| 扫描件 PDF | 先只支持文本型 PDF |
| 跨章节语义检索 | 当前上下文已够用 |
| 全书内容自动召回 | 简化上下文模型 |
| 长期阅读记忆 | 增加复杂度 |
