# 回复操作与会话快捷操作设计

> 日期：2026-08-02  
> 状态：设计已确认，待规格审阅  
> 范围：代码分析工作台中每条 AI 回复的操作栏，以及项目侧边栏中的会话操作菜单。

## 1. 目标

让用户能从每条已完成的 AI 回复直接执行复制、回退、分支和导出；让侧边栏会话菜单也能针对该会话的当前回复执行分支和导出。移除侧边栏底部独立的导出入口，避免同一能力出现互相割裂的入口。

本设计沿用当前产品语义：**分支会创建一个独立的新会话副本**，而非在原会话中创建可见分支树。

## 2. 已确认的交互

### 2.1 单条回复操作栏

- 每一条状态为 `completed` 且具有关联 `documentId` 的 AI 回复下方显示一排操作：`复制`、`回退`、`分支`、`导出`。
- 操作使用 Material Symbols 图标，并提供可见文字或无障碍名称与悬浮提示；不使用 emoji。
- `复制` 将该条回复的 Markdown 内容写入系统剪贴板。成功与失败均提供短暂、可读的反馈。
- `回退` 将当前会话切换到这条回复；当前已打开的回复不重复执行，按钮禁用或以当前状态呈现。
- `分支` 以该回复为分叉点创建独立会话副本，并在成功后选中新会话。复制内容包含从首轮到分叉点的历史、批注和讨论记录，沿用既有后端实现。
- `导出` 提供 Markdown 与 JSON 两种格式，复用现有导出逻辑，并通过保存文件对话框写出文件。
- 生成中、失败、用户消息和没有 `documentId` 的占位回复不显示该操作栏，避免错误地操作不完整内容。

### 2.2 侧边栏会话操作

- 每个会话的更多操作菜单保留既有会话级操作，并新增 `分支` 与 `导出`。
- 这两个操作都作用于该会话的 `activeDocumentId`：`分支` 从其当前回复创建独立副本；`导出` 导出其当前回复。
- 会话没有当前回复时，两个菜单项禁用，并以无障碍提示说明原因。
- 导出仍提供 Markdown 与 JSON 格式选择；侧边栏菜单的二级选择与回复操作栏保持一致。
- 删除工作台侧边栏底部的独立导出菜单与不再使用的样式、导出。

## 3. 实现边界

### 包含

- 在 `CodeAnalysisWorkbench` 的 AI 回复渲染处添加回复操作栏，并把既有的回退、分支、导出处理函数按回复 ID 复用。
- 为复制行为添加一个小而独立的 UI 辅助函数或事件处理器，使用浏览器 Clipboard API 并处理拒绝权限或运行环境不可用。
- 扩展 `ProjectSidebar` 的会话更多菜单与必要回调，使其能够把会话的活动回复 ID 传回工作台处理。
- 删除 `ExportMenu` 作为独立侧边栏入口的渲染和无用引用。
- 补足中英文可访问标签、提示文字及成功/失败反馈。

### 不包含

- 不改动 SQLite 架构、IPC 契约或独立会话分支的业务规则。
- 不新增文件格式；继续支持现有 Markdown 与 JSON 导出。
- 不引入会话内分支树、跨会话合并或版本历史重写能力。

## 4. 数据与调用流

```text
AI 回复（documentId）
  ├─ 复制   → Clipboard API
  ├─ 回退   → checkoutTurn(sessionId, branchId, documentId)
  ├─ 分支   → forkSession(sessionId, documentId) → 选中新独立会话
  └─ 导出   → exportDocument(documentId, markdown | json) → 保存文件

会话更多菜单（activeDocumentId）
  ├─ 分支   → forkSession(sessionId, activeDocumentId)
  └─ 导出   → exportDocument(activeDocumentId, markdown | json) → 保存文件
```

现有主进程 IPC 和会话复制实现保持不变；渲染层仅补齐入口、参数传递与状态反馈。

## 5. 异常与状态

- 剪贴板写入失败：不改变页面数据，显示“复制失败，请重试”。
- 分支或导出失败：保留现有错误显示机制；不切换会话、不清空当前内容。
- 操作进行中：对应按钮临时禁用，防止重复创建会话或重复打开保存对话框。
- 缺少回复 ID、会话 ID 或当前回复：不调用 IPC；入口隐藏或禁用。
- 所有操作均可通过键盘聚焦和激活；图标按钮具有明确的 `aria-label`。

## 6. 测试与验收

遵循 Red → Green → Refactor：先添加失败的 Vitest 渲染测试，再接入最小实现。

- `CodeAnalysisWorkbench`：已完成 AI 回复显示四项操作；复制成功和失败反馈；回退、分支、两种导出格式传递正确参数；当前回复与无 ID 回复的禁用/隐藏状态。
- `ProjectSidebar`：会话菜单显示分支与导出；会话活动回复 ID 被正确传递；没有活动回复时禁用；删除独立导出入口后不再渲染。

- 回归：运行桌面端相关 Vitest 测试及 `pnpm --filter @ai-reader/desktop type-check`；覆盖新增逻辑的正常、边界与失败路径。

## 7. 规格自检

- 不存在待定的交互或格式选择：导出支持 Markdown 与 JSON，分支创建独立会话副本。
- 每个入口都以明确的回复 ID 为操作对象；会话入口统一使用该会话的活动回复。
- 改动范围限制在渲染层与现有测试，不改变数据模型和后端协议。
